# Мёртвая зона по току: причина найдена в коде и в физике инвертора

Этап v0.9C §11-§13. Документ закрывает блокер 9b.

Источники: `vedderb/bldc`, ветка `release_6_06` — та же, что на стенде
(прошивка 6.6, hw 410). Файлы `motor/mcpwm_foc.c`, `motor/mc_interface.c`,
`comm/comm_can.c`, `motor/mcconf_default.h`.

---

## 2. Что проверено и отвергнуто

| Кандидат | Вердикт | Основание |
|---|---|---|
| `l_min_duty` | **ОТВЕРГНУТ** | в `mcpwm_foc.c` не упоминается ни разу: это параметр режима BLDC, не FOC |
| `cc_min_current` | **ОТВЕРГНУТ** | `mcpwm_foc.c:808` — порог 0.05 А, в шесть-восемь раз ниже наблюдаемого |
| мёртвая зона регулятора | **ОТВЕРГНУТ** | `mcpwm_foc.c:4543-4553` — честный ПИ с интегратором, никакого deadband |
| MTPA | **ОТВЕРГНУТ** | `foc_mtpa_mode = 0` в обеих половинах, блок не исполняется |
| предел входного тока через `mod_q` | **ОТВЕРГНУТ** | `mcpwm_foc.c:3564-3567` неактивен при \|mod_q\| < 0.001, а выше даёт пределы в сотни ампер |
| фильтрация `iq_set` | **ОТВЕРГНУТ** | `iq_set_tmp = m_iq_set` напрямую |
| `cc_ramp_step_max` | **ОТВЕРГНУТ** | в FOC не используется |
| переход наблюдатель/Холл | **ОТВЕРГНУТ** | порог одинаков при 0 и 460 об/мин |
| минимальные ERPM | **ОТВЕРГНУТ** | `s_pid_min_erpm` относится к режиму скорости |

| разрешение датчика тока | **НЕИЗВЕСТНО** | может добавлять к остаточному отставанию |

## 3. Механизм

Мёртвое время силового каскада создаёт ошибку фазного напряжения

```
ΔV = V_bus · t_dead · f_sw
```

знак которой следует за направлением тока. VESC компенсирует её **только в
измерительном тракте** — `update_valpha_vbeta()`, `mcpwm_foc.c:5012-5017`,
где поправка вычитается из `mod_alpha`/`mod_beta` для наблюдателя. **На выходе
компенсации нет.**

Напряжение, нужное для тока `I` на стоящем моторе, равно `I · R`. Порог, где
одно сравнивается с другим:

```
I_порог = V_bus · t_dead · f_sw / R
```

Числа из конфигурации обеих половин:

```
V_bus    40.5 В         t_dead  0.12 мкс (foc_dt_us)
f_sw     25 000 Гц      R       0.3188 Ом (118) / 0.3162 (100)

ΔV      = 40.5 × 0.12e-6 × 25000 = 0.1215 В
I_порог = 0.1215 / 0.3188        = 0.381 А
```

Ниже этого тока ошибка мёртвого времени **превышает всё полезное
напряжение**. Поскольку знак ошибки разрывно зависит от направления тока,
интегратор ПИ не может её скомпенсировать: ток дёргается вокруг нуля без
среднего значения. Это и есть слышимый стрёкот при нулевом измеренном токе.

## 4. Сравнение с измерением

```
предсказано                        0.381 А
первый отклик, измерено            0.30 А
устойчивое вращение, измерено      0.40 А
начало торможения, измерено       −0.30 А
```

Предсказание попадает между первым откликом и устойчивым вращением.
Расхождение в пределах 25 % объясняется тем, что `I · R` — не всё напряжение:
интегратор частично выбирает ошибку, когда ток удерживает один знак.

## 5. Почему это объясняет и независимость от скорости

Решающее наблюдение v0.9B: на вращающемся колесе порог **тот же**, что с
места, — именно оно исключило механику.

Механизм это объясняет полностью. Ошибка мёртвого времени не зависит от
скорости: в неё входят только напряжение шины, мёртвое время и частота ШИМ.
Противо-ЭДС добавляется к обеим сторонам уравнения и сокращается. Значит
ошибка **по току** остаётся равной `ΔV / R ≈ 0.38 А` на любой скорости — и
порог не двигается.

Ни одна из отвергнутых версий этого не объясняла: `l_min_duty` при вращении не
действует вовсе, трение покоя при вращении отсутствует, переход
наблюдателя зависит от скорости по определению.

## 6. Остаточное отставание

Выше порога измеренный ток отстаёт от команды примерно на 0.10 А:

```
команда  0.40  0.50  0.60  0.75  1.00
ток      0.17  0.30  0.42  0.62  0.90
```

Это меньше полной ошибки мёртвого времени (0.38 А), то есть интегратор её
частично выбирает — но не полностью, потому что ошибка разрывна на переходах
тока через ноль внутри периода ШИМ. Точное разделение вклада интегратора и
разрешения датчика тока не проводилось.

## 7. Уверенность и что осталось открытым

```
механизм подтверждён кодом и конфигурацией    высокая
количественное совпадение (0.38 против 0.30-0.40)  хорошая
остаточное отставание 0.10 А                  объяснено частично
вклад разрешения датчика тока                 НЕ ИЗМЕРЕН
```

Открытые вопросы: почему первый отклик (0.30 А) наступает ниже расчёта;
какова доля датчика тока в остаточном отставании; насколько несимметричность
(торможение с −0.30 А против разгона с +0.40 А) объясняется тем же
механизмом.

## 8. Никакой компенсации не вводится

ТЗ прямо это запрещает, и правильно. Теперь, когда механизм известен, видно,
что лечить симптом было бы особенно неудачно: мёртвое время — свойство
силового каскада, и компенсируется оно на уровне модуляции, а не поправкой в
задании балансировочного контура. Направления для отдельного решения:
компенсация мёртвого времени на выходе (её в прошивке нет), повышение частоты
ШИМ, либо явный учёт мёртвой зоны в контуре. Выбор — отдельный этап.
