# Модель батареи и напряжений

Документ этапов v0.7D и v0.7D.1. Батарея — **10S Li-ion**, подтверждено
владельцем. **Все шесть изменений применены и пережили полный цикл питания**
(v0.7D.1); порядок применения и побайтовые доказательства — в
[`esc_config_checkpoint.md`](esc_config_checkpoint.md).

Проверки в исполняемом виде: `compat/safety/fc_battery_model.{h,c}`,
тесты — `tests/safety/test_motor_prep.c`.

---

## 1. Три числа ячеек, два из которых были неверны

| Где | Было | Стало | Кто это читает |
|---|---|---|---|
| Прошивка ESC, `si_battery_cells` | **3** | **10** (применено на обеих половинах) | только оценка остатка заряда самим ESC |
| FloatCore, `floatcore_limits.c` | 20 | **10** | путь host и протокол |
| FloatCore, `fc_vesc_if.c` | **15** | **10** | **Refloat на плате** |

Числа не дублируют друг друга, и путать их нельзя: Refloat работает на ESP32
против нашего `VESC_IF`, поэтому он видит **наше** число, а не то, что стоит
в ESC. Именно наше и было самым вредным.

После правки оба места FloatCore берут значение из одного источника —
`fc_battery_cell_count()`, а он защищён от нуля: `FC_BATTERY_CELLS_DEFAULT`.
Ноль здесь особенно коварен, потому что Refloat умножает пороги на число
ячеек **только если оно больше нуля** (`motor_data.c:80`), иначе трактует
«3.0 В» как абсолютный порог для всей батареи, и откат не срабатывает никогда.

## 2. Кто чем управляет

**Защиты прошивки ESC числом ячеек не пользуются вовсе.** Они работают в
абсолютных вольтах (`mc_interface.c:2440-2458`). Неверное `si_battery_cells`
их не ослабляет — это единственная причина, по которой ошибка прожила так
долго незамеченной.

**`si_battery_cells` в прошивке ESC** используется в одном месте: оценке
остатка заряда `mc_interface_get_battery_level()` (`mc_interface.c:1560-1580`).

**У Refloat он влияет на безопасность:**

```c
// refloat-upstream/src/motor_data.c:79-88
uint8_t battery_cells = VESC_IF->get_cfg_int(CFG_PARAM_si_battery_cells);
if (battery_cells > 0) {
    if (lv_threshold < 10) lv_threshold *= battery_cells;
    if (hv_threshold < 10) hv_threshold *= battery_cells;
}
```

## 4. Политика низкого напряжения

**Применено: `tiltback_lv = 3.6 В/ячейку` (36.0 В).**

На v0.7D предлагалось 3.5 В/яч по рассуждению «отсечка ESC 34 В плюс 1 В на
просадку». Это **двойной счёт**: у Refloat есть собственная модель просадки, и
надо было смотреть на неё, а не считать заново.

`refloat-upstream/src/main.c:614-622`:

```c
float abs_motor_current = fabsf(d->motor.dir_current);   // ток МОТОРА
float vdelta = d->motor.lv_threshold - d->motor.batt_voltage;
float ratio  = vdelta * 20 / abs_motor_current;
// a) мы на 2 В ниже порога
// b) ток мал, просадку предполагать нельзя
// c) больше 20 А на вольт разницы — просадку терпим
if ((vdelta > 2) || (abs_motor_current < 5) || (ratio > 1) || ...)
```

Встроенный коэффициент 20 А на вольт — это модель внутреннего сопротивления
50 мОм, ровно та, которую я считал руками.

### Где это ломается

Порог 35 В, ток мотора 20 А, напряжение просело до 34 В:

```
vdelta = 1        не > 2
ток    = 20 А     не < 5
ratio  = 1·20/20 = 1.0   не > 1
```

**Отката нет**, а ESC на 34 В уже начал срезать входной ток. Проверка
«35 > 34» этого не ловила.

### Отсюда правило

Единственная ветка, срабатывающая при **любом** токе, — `vdelta > 2`. Значит

```
порог − 2 ≥ l_battery_cut_start
порог ≥ 34.0 + 2.0 = 36.0 В = 3.6 В/ячейку
```

При малом токе (< 5 А) откат приходит гораздо раньше — уже на 36 В. При
большом — не позже начала срезания. Обе границы заданы, а не выбраны.

Цена честная: при малом токе предупреждение на 36 В, а это около половины
заряда. Если нужен больший запас хода, правильное действие — опустить
`l_battery_cut_start` (сейчас 3.4 В/яч, консервативно), а не откладывать
предупреждение. Порог и отсечка двигаются вместе: между ними обязаны
оставаться те же 2 В.

## 5. Политика высокого напряжения — зеркальная задача, и она хуже

**Применено: `tiltback_hv = 4.0 В/ячейку` (40.0 В).**

Значение Refloat по умолчанию 4.3 В/яч даёт 43.0 В. Для 10S полностью
заряженная батарея — **42.0 В**. Порог физически недостижим: предупреждение
о высоком напряжении **не сработает никогда**. При этом ESC начинает срезать
рекуперацию с 41.5 В и обнуляет её на 42.0 В.

Для доски это опаснее низкого напряжения: рекуперативное торможение и есть
способность остановиться. Потерять её молча, съезжая с горки на
свежезаряженной батарее, — известный сценарий падения.

### Почему 4.1 из v0.7D не подошло

`main.c:523-540`: откат при `duty > 0.05` и `batt > порог`, но только если
прошло **500 мс** либо напряжение выше порога **на целый вольт**.

При 4.1 В/яч (41.0 В) немедленная ветка срабатывает на **42.0 В** — там, где
рекуперация уже срезана полностью. Поздно.

```
порог + 1 ≤ 41.5  →  порог ≤ 40.5 В
```

**4.0 В/ячейку**: немедленная ветка на 41.0 В — за 0.5 В до начала срезания;
ветка 500 мс — за 1.5 В.

Следствие, которое надо принять осознанно: на батарее выше 40 В доска будет
давать откат. Это верхняя четверть заряда, и это правдивый сигнал —
рекуперативного торможения там действительно нет. Поднять regen-отсечку
вместо этого нельзя: 4.2 В/ячейку — предел химии.

### Дополнительный слой, и он оказался не тем, чем казался

`l_in_current_min = 0.0`. На v0.7D записано, что это «запрещает ток в батарею,
а тормозная способность ограничена тем, что ESC может рассеять». **Вторая
половина фразы неверна**, и разбор в `motor_parameter_model.md` §9 показывает
почему: рассеивать нечего, потому что тормозного момента не возникает вовсе.

Кратко: ограничение накладывается не на ток батареи, а на `iq`, и делится на
`mod_q` (`mcpwm_foc.c:3564-3567`). При нуле нижняя граница равна `0/mod_q` =
ровно ноль, то есть отрицательный момент зажат в ноль, пока колесо вращается.

Для полной батареи это действительно снимает вопрос regen — но ценой того, что
тормозить нечем. Решение принято: **−1 А**, применяется вместе с остальными
пределами первого прокрута.

## 6. Лабораторный источник и первый прокрут

**30 В лабораторника — это стенд для софта и CAN, и ничего больше.**

```
v_in измерено через CAN: 30.3 В (ID 118), 30.1 В (ID 100)
l_battery_cut_end = 31.0 В
```

При таком напряжении ESC держит входной ток **ровно нулём**
(`mc_interface.c:2442`: `v_in < cut_end + 0.1` → `lo_in_max_batt = 0`).
Попытка получить вращение на 30 В даст ложный отрицательный результат: мотор
не крутится не потому, что что-то сломано, а потому что ток запрещён.

**Отсечки под лабораторник НЕ снижаются.** Это защита батареи, а не помеха
тесту. Снизить 34/31 В ради удобства стенда означало бы отключить защиту
ровно в тот момент, когда впервые появится реальный ток.

### Первый физический прокрут — от реальной 10S батареи

* Проверить напряжение мультиметром до подключения.
* **Не брать батарею на абсолютных 42.0 В.** При полном заряде regen срезан, а
  применённый порог отката 40.0 В сработает сразу. Разумный диапазон для
  первого теста — примерно **37-40 В**, то есть 3.7-4.0 В на ячейку. Выше
  41 В — оценить запас по рекуперации до прокрута; на 34 В и ниже тест не
  проводить вовсе.
* Колесо вывешено, доска закреплена, человек на доске не стоит, зона
  вращения свободна.

## 7. Что остаётся несогласованным

| Что | Состояние |
|---|---|
| FloatCore, число ячеек | **10, применено (v0.7D)** |
| ESC, `si_battery_cells` | **10 на обеих половинах, применено (v0.7D.1)** |
| Refloat `tiltback_lv` | **3.6 В/яч, применено (v0.7D.1)** |
| Refloat `tiltback_hv` | **4.0 В/яч, применено (v0.7D.1)** |
| `l_in_current_min = 0.0` | **решено: −1 А вместе с пределами первого прокрута**, не применено |

Модель батареи **непротиворечива**: `fc_battery_model_valid()` на применённых
значениях (10 ячеек, отсечки 34/31, regen 41.5/42.0, пороги 3.6/4.0)
возвращает true. Этот пункт больше не блокирует моторный этап.

Остаётся `l_in_current_min`: решение принято (−1 А), применение отложено до
момента непосредственно перед первым прокрутом, вместе с остальными
пределами тока.
