## E. Объяснение исполнения > периода

Метрика `exec` в `fc_timing.c:182` — **настенное** время между пробуждением и
засыпанием. Вытеснение задачами повыше входит в него целиком, ожидание внутри
измеряемого участка — тоже. Читать `exec > период` как «итерация непрерывно
занимала процессор дольше периода» **неверно**.

Добавлен прямой учёт: глобальный накопитель занятости ядра, разность отсчётов
внутри итерации даёт чужую работу, `net = exec − вытеснение`. Учитываются
только инструментированные каналы, поэтому `net` — оценка **сверху**.

Результат: собственное CPU `refloat_thd` max **1333 мкс** при периоде 2000.
Блокер §10 в штатном режиме НЕ выполняется.

Попутно найдена дыра в учёте: супервизор работает на том же ядре 100 раз в
секунду и не был инструментирован, поэтому его время записывалось в
«собственное CPU» вытесненных задач. Добавлен канал `fc_super`: 190.6 мкс
среднего при пустой очереди зазоров.

## G. Ограждение замкнутого контура

Четыре независимых условия, ни одно не выводится из других:

```
FLOATCORE_MOTOR_EXPERIMENTAL                  профиль сборки
FLOATCORE_MOTOR_EXPERIMENTAL_WHEEL_OFF_GROUND подтверждение вывешенного колеса
FLOATCORE_CAN_ACTIVE_MOTOR                    профиль шины
FLOATCORE_REFLOAT_REAL_MOTOR_LOOP             сам флаг контура
```

Плюс два условия времени выполнения: явное включение источника REFLOAT в маску
гейта и вооружение координатора. `fc_motor_gate_set_allowed_origins()` теперь
физически не может поставить бит REFLOAT — иначе вся надстройка была бы
декоративной.

Окна входа выведены из оболочки по правилу «вход не должен начинаться в
насыщении», а не назначены числом:

```
угол     < оболочка / (А на градус)     = 1.5 / 2.73   = 0.549°
скорость < оболочка / (А на °/с)        = 1.5 / 0.0819 = 18.3 °/с
```

Собственный порог Refloat `startup_pitch_tolerance = 4°` оставлен потолком:
ослаблять условие engage самого Refloat мы не вправе.

## H. БЛОКЕР: отказ реального времени

Один и тот же код, одна и та же плата, Refloat в RUNNING:

| | task_wdt | missed (control/refloat/super) | собств. CPU refloat mean / max | худшая транзакция I²C |
|---|---|---|---|---|
| LAB_SAFE + RUNNING | 0 | 0 / 0 / 0 | 571.5 / 1762 мкс | 1140 мкс |
| EXP + RUNNING, не вооружён | 6 | 0 / 4 / 0 | 1017.7 / 2699 мкс | 1147 мкс |
| EXP + RUNNING, ВООРУЖЁН | 222 | 18 / 52 / 18 | 1052.3 / **21091** мкс | **32896** мкс |
| EXP + вооружён, НЕ running | 0 | 0 / 0 / 0 | 337.5 / 1333 мкс | — |

Нужны ОБА условия — экспериментальный профиль и RUNNING; вооружение усиливает
эффект на порядок. Ни моторный транспорт сам по себе (нагрузка 500 Гц чиста),
ни RUNNING сам по себе блокером не являются.

**Причина не установлена.** Что исключено измерением: ошибки CAN (0), потери
журнала (0), рост кучи (стабильна), появление лишней задачи на ядре 1 (нет),
стоимость пути гейта (три счётчика, запрос отвергается до backend-а).

Что исключить не удалось:
* активность flash — трассировка зазоров пишет «flash занят: НЕИЗВЕСТНО (нет
  телеметрии)», а запись во flash на ESP32 останавливает оба ядра, отключая
  кэш;
* нагрузку TWAI в режиме ACTIVE_MOTOR против ACTIVE_DIAG.

Разделить профиль сборки и профиль шины нельзя: `fc_build_profile.h` запрещает
собрать экспериментальный профиль с диагностическим CAN. Ослаблять эту защиту
ради замера недопустимо.
