# Контракт безопасности моторного вывода

Этап v0.8C. Документ описывает архитектуру, которой **ещё нет в железе**:
профиль `MOTOR_CAPABLE` не создан, транспорт моторных команд не реализован,
`Motor Gate allowed = 0, sent = 0, backend = none`.

Каждое утверждение в §14 классифицировано: доказано тестом, доказано кодом,
проектное решение, допущение или открыто. Смешивать эти категории — самый
дешёвый способ получить архитектуру, которая выглядит обоснованной, не будучи
ею.

Реализация: `compat/motor/fc_dual_motor.{h,c}`, `compat/motor/fc_motor_transport.h`.
Тесты: `tests/safety/test_motor_backend.c`, `tests/can/negative_dual_backend.c`.

---

## 1. Слои и кто за что отвечает

```
 A  Refloat / контур              формирует требуемый ток, 500 Гц
            │
            ▼  VESC_IF->mc_set_*
 B  Motor Gate                    ИМЕЕТ ЛИ ПРАВО команда существовать
            │                     (состояние Supervisor, backend, диапазон)
            ▼
 C  Dual Motor Coordinator        ЧТО ИМЕННО получат две половины
            │                     (разрешение по свежести и здоровью, знак,
            │                      предел, порядок, защёлка)
            ▼
 D  Транспорт моторных команд     ЕДИНСТВЕННОЕ место сериализации
            │                     В ЭТОЙ СБОРКЕ НЕ СУЩЕСТВУЕТ
            ▼
        TWAI ──► ESC 118, ESC 100
            │
 E  Наблюдатель здоровья узлов ◄──┘  независимо, только запрещает
 F  Сторожевой таймер                своя граница 20 мс, чужая 50 мс
```

Разделение B и C — не педантизм. Motor Gate отвечает на вопрос о праве и
ничего не знает про две половины; координатор отвечает за содержание и не
знает про профиль сборки. Слив их, мы получили бы место, где решение о
безопасности принимается вперемешку с арифметикой, и проверять пришлось бы
всё сразу.

**Наблюдатель E только запрещает.** Направление зависимости выбрано так ещё
на v0.7B: соблазн «оба VESC здоровы, значит можно» создал бы второй путь к
моторной команде, и проверять пришлось бы уже не одно место.

## 2. Семантика величины

```
requested_current_a  =  ток ОДНОГО мотора
```

Не сумма по доске и не «момент, который надо разделить». Каждая половина
получает значение **целиком**.

Соглашение не выбрано заново, а взято из уже существующего: Refloat построен
вокруг одного мотора, `logical_motor.h` фиксирует то же самое с v0.2, а
`motor_semantics.md` агрегирует ток обратно **средним, а не суммой**. Любое
другое толкование на любом из трёх стыков даёт вдвое больший или вдвое
меньший момент, причём молча.

Момент доски при запросе `I`:

```
M = I · (kt_A + kt_B) = I · (0.441 + 0.449) = I · 0.890 Н·м/А
```

**Помоторного масштабирования не вводится.** Разница потокосцеплений 1.84 %
меньше, чем неопределённость любой другой величины в этой цепочке: диаметр
колеса не подтверждён вовсе, сопротивление обмотки на нынешних пределах не
измеряется (±20 %). Усложнять backend ради 1.8 % при таком фоне — значит
создать себе ещё одно место для ошибки, не уменьшив ни одной.

## 3. Знак

Физически доказано на v0.8B: положительная команда **обеим** половинам даёт
движение вперёд (верх колеса к носу).

```
положительный момент доски  ->  положительная команда 118
                            ->  положительная команда 100
```

Скрытых инверсий нет. Поле `invert[]` в конфигурации существует, по умолчанию
выключено на обеих половинах, и его действие проверяется тестом. Требование
§7 читается буквально: будущая инверсия обязана быть видна в конфигурации и в
отчёте, а не спрятаться минусом внутри транспорта.

## 4. Условия разрешения

Все проверяются **одновременно**, и отказ возвращает маску всех невыполненных
условий, а не первое. Иначе чинить приходится по одному, каждый раз заново
угадывая, что ещё не так.

| Условие | Граница | Что ловит |
|---|---|---|
| разрешение запрошено | — | случайная тяга после перезапуска |
| Supervisor разрешает | — | любое состояние, кроме рабочего |
| защёлка снята | — | возврат тяги после отказа «сам собой» |
| прошлая пара ушла целиком | — | разошедшиеся половины |
| семпл IMU свеж | 20 мс | управление по устаревшему углу |
| команда контура свежа | 20 мс | остановка источника |
| обратная связь A свежа | 60 мс | молчание половины |
| обратная связь B свежа | 60 мс | то же |
| `mc_fault_code` A = 0 | — | отказ половины |
| `mc_fault_code` B = 0 | — | то же |
| шина не в BUS_OFF | — | потеря шины |
| шина не деградировала | — | error passive, рост счётчиков |
| значение не NaN и не Inf | — | разрушенный расчёт |
| значение в пределе | ±5 А | ошибка расчёта, дающая предельный ток |

Последняя строка **запрещает, а не насыщает**. Насыщение превратило бы ошибку
расчёта в тихо принятую команду предельной величины — худший из возможных
исходов для доски под человеком.

Порог молчания половины (60 мс) осознанно **длиннее** командного (20 мс):
периодический STATUS идёт 50 Гц, и три подряд пропущенных кадра — это уже не
единичная потеря. Подтверждать отказ половины поспешнее, чем собственный сбой,
неправильно: собственный сбой мы видим достоверно, чужое молчание — нет.

## 5. Состояния

```
          init
            │
            ▼
      NOT_ARMED ──arm()──► EVALUATING ──все условия──► PERMIT
            ▲                  │                          │
            │                  │ хоть одно не выполнено   │ пара уходит
            │                  ▼                          ▼
            │                DENY ◄──────────────── частичная передача
            │                  │                          │
            │                  │                          ▼
            └──clear_latch()──┴──────────────────────► LATCHED
                              (только явным действием)
```

Два свойства, каждое проверено тестом:

**Защёлка не снимается исправностью.** Возврат исправных входов оставляет
запрет: `LATCHED` снимается только `clear_latch()`.

**Снятие защёлки не разрешает тягу.** После `clear_latch()` система
оказывается в `NOT_ARMED`, и разрешение надо запросить заново. Одна команда
оператора не должна снимать два барьера сразу.

**Перезапуск не является способом снять защёлку** — после `init` состояние
`NOT_ARMED`, а не «как было».

## 6. Отсутствие команды — это тишина, а не ноль

При любом запрете не передаётся **ничего**, в том числе нулевая команда.

Нулевая команда — тоже команда: она вызывает `timeout_reset()` на ESC
(`comm_can.c:1590…1619`) и продлевает чужой сторожевой таймер, то есть
сообщает половине «контроллер жив» ровно тогда, когда он не жив. При отказе
нужно обратное: молчание, чтобы сработал таймаут.

Отсюда же следует, что прошлое значение никогда не повторяется: план при
запрете пуст, а не «как в прошлый раз» (инвариант I10).

## 7. Политика при отказе одной половины

Выбрана **симметричная**:

```
отказ или молчание ЛЮБОЙ половины
        ->  разрешение отозвано
        ->  ОБЕ половины перестают получать команды
        ->  сторожевой таймер ESC снимает тягу выбегом
```

**Это не значит, что политика окончательная.** «Один жив — едем на одном» не
принимается без отдельного физического доказательства, но и симметричный
выбег имеет цену, которую надо назвать вслух: для балансирующей платформы
одновременная потеря тяги на обеих половинах — это падение. Разница лишь в
том, что падение предсказуемо и симметрично, тогда как езда на одном моторе
из двух, сидящих на **одной оси**, означает, что второй мотор превращается в
тормоз (зубцовый момент и, при коротком замыкании фаз в фолте, генераторное
сопротивление). Асимметричный момент на одноколёсной доске — это рывок в
сторону, а не мягкая деградация.

Именно поэтому симметричный выбег выбран **для первой версии**: он даёт
предсказуемое поведение, которое можно проверить на вывешенном колесе, а не
поведение, правдоподобность которого приходится обсуждать.

| # | Сценарий | Поведение |
|---|---|---|
| A | 118 молчит, 100 жив | обе перестают получать команды, выбег |
| B | 100 молчит, 118 жив | то же |
| C | fault 118 | то же |
| D | fault 100 | то же |
| E | передача удалась одной, не удалась второй | защёлка, обе перестают, выбег |
| F | шина деградировала | запрет, выбег |
| G | BUS_OFF | запрет, выбег |
| H | перезапуск FloatCore | команды прекращаются мгновенно, ESC снимает тягу за 60 мс |
| I | остановка задачи контура | команда устаревает за 20 мс, запрет |
| J | IMU_UNHEALTHY | запрет по устаревшему семплу, 20 мс |
| K | Supervisor в FAULT | запрет немедленно |

## 8. Окно асимметрии

CAN не даёт атомарной записи двум независимым ESC. Значит между командой
половине A и командой половине B существует окно, и его надо не объявлять
малым, а посчитать.

### Отказ, видимый сразу (транспорт вернул false)

Половина A получила команду N, половина B осталась на N−1, которая на один
период контура старше. Обе перестают обновляться.

```
A выбегает   t_N     + 50 мс, округление до тика 10 мс
B выбегает   t_N − 2 + 50 мс, то же
разница      2 мс + округление  ≤ 12 мс
```

### Тихий отказ (кадры уходят, половина не исполняет)

Обнаруживается только устареванием обратной связи.

```
обнаружение             ≤ 60 мс
+ таймаут ESC             50 мс
+ округление до тика      10 мс
худшая асимметрия      ≤ 120 мс
```

Это число возвращает `fc_dual_motor_worst_asymmetry_us()` и проверяет тест —
чтобы оно не разошлось с константами при правке.

### Разбег внутри пары

Передача последовательная, порядок фиксирован: сначала A, затем B.
Чередование не вводится — оно усложняет разбор отказа («в каком порядке шло
на этот раз?»), а атомарности всё равно не создаёт.

```
кадр 8 байт, расширенный идентификатор, 500 кбит/с   ≈ 256 мкс
объявленная граница FC_DUAL_MAX_SKEW_US               1000 мкс
доля от таймаута ESC                                    2 %
```

Величина 256 мкс — **расчёт**, а не измерение: на реальной шине к ней
добавится арбитраж. Измерить на железе можно только после появления
транспорта, и до тех пор это допущение.

## 9. Хронология сторожевого таймера

```
темп команд          2 мс      контур 500 Гц
свой таймаут        20 мс      4 пропуска подряд + запас
таймаут ESC         50 мс      timeout_msec, применён на обеих половинах
тик ESC             10 мс      поток Timeout просыпается раз в 10 мс
timeout_brake        0.0       выбег, не торможение
```

Худшее удержание тяги при **полном** отказе FloatCore, когда ни один наш
барьер не работает (перезагрузка, зависание):

```
50 мс таймаут + 10 мс округление = 60 мс
```

Наш барьер при обнаруживаемом отказе срабатывает за 20 мс, то есть втрое
раньше чужого. Это и есть смысл выбранных чисел: собственная защита обязана
успевать первой, а чужая — оставаться страховкой, а не основным механизмом.

## 10. NaN, Inf и диапазон

`NaN` и `Inf` отвергаются отдельной причиной, а не проваливаются в сравнение
с пределом: сравнение с `NaN` ложно в обе стороны, и проверка «по модулю не
больше предела» пропустила бы `NaN` как допустимое значение. Это классическая
ошибка, и тест на неё есть.

## 11. Перезапуск

После `init` координатор в `NOT_ARMED`. Ни защёлка, ни разрешение, ни прошлая
команда не переживают перезапуск. Отдельный сценарий матрицы проверяет, что
перезапуск **не** является способом снять защёлку.

## 12. Чего в этой сборке нет

```
FLOATCORE_MOTOR_CAPABLE          не определён нигде
FC_MOTOR_BACKEND_AVAILABLE       0
fc_motor_gate_set_backend        прототип объявлен только вне LAB_SAFE
сериализатор моторных команд     отсутствует как код, имена отравлены
белый список диагностики         5 запросов, все read-only, без изменений
```

Интерфейс транспорта (`fc_motor_transport.h`) объявлен и в LAB_SAFE — намеренно.
Иначе его нельзя было бы проверить: тестовая реализация, записывающая вызовы в
массив, физически неспособна что-либо передать, но позволяет прогнать все
отказные сценарии до того, как появится настоящая. Отсутствие интерфейса не
сделало бы прошивку безопаснее — оно сделало бы её непроверенной.

Граница проходит не по объявлению, а по реализации.

запрещает всё подряд по любому поводу.

половины разошлись.

## 15. Что этот этап не делает

Не создаёт `MOTOR_CAPABLE`, не реализует транспорт, не расширяет белый список
CAN, не включает замкнутую балансировку, не поднимает пределы тока.

Архитектура существует как проверяемая модель и как набор доказательств того,
что физического выхода нет. Переход к экспериментальной прошивке с моторным
выводом — отдельное решение и отдельный этап.
