# Резервная копия конфигурации VESC — v0.7D.1

Снята **до** первых изменений конфигурации (этап v0.7D.1), через CAN
средствами FloatCore, обе половины Dual FSESC.

Это состояние **до** записи. Применённые после неё изменения перечислены в
`docs/esc_config_checkpoint.md` §3.

## Что здесь

| Файл | Что это |
|---|---|
| `mcconf_id118.bin` | ответ `COMM_GET_MCCONF` половины 118 целиком, 484 Б |
| `appconf_id118.bin` | ответ `COMM_GET_APPCONF` половины 118, 279 Б |
| `mcconf_id100.bin`, `appconf_id100.bin` | то же для половины 100 |
| `fw_id118.bin`, `fw_id100.bin` | `COMM_FW_VERSION`: версия, железо, UUID |
| `*.json` | те же байты в hex плюс разобранные поля и сигнатура |

**Первый байт `.bin` — номер пакета COMM**, а не данные конфигурации. Сама
сериализованная конфигурация начинается со второго байта, и первые её четыре
байта — сигнатура раскладки (`2efd0142` у mcconf, `7d217eb8` у appconf).

Файлы лежат в репозитории намеренно: копия, существующая только на одном
ноутбуке, — не копия. Суммарный размер около 1.6 КБ.

## Как проверить, что копия цела

```
python3 tools/vesc_backup.py --log <вывод can-diag-hex> --out /tmp/check
```

Инструмент печатает разобранные поля и сверяет записанное с прочитанным.

## Как сравнить текущее состояние с этой копией

```
python3 tools/vesc_diff.py \
    --before backups/vesc/v0.7d1/mcconf_id118.bin \
    --after-log <вывод can-diag-hex mcconf 118> \
    --request GET_MCCONF --id 118
```

Расхождения в `foc_offsets_current[0..2]` и `foc_offsets_voltage[0..2]` —
ожидаемы: ESC перемеряет их при каждом включении. Всё остальное означает, что
конфигурацию кто-то менял.
