# Неподдерживаемые команды

FloatCore реализует минимум, необходимый VESC Tool для подключения, телеметрии,
UI Refloat и конфигурации. Всё остальное сознательно не реализовано.

## Правило обработки

| Класс | Поведение | Ответ | Счётчик |
|---|---|---|---|
| Команды управления мотором | **блокируются**, логируются в трассировке | нет | `motor_commands_blocked` |
| Известные, но не реализованные | тихо игнорируются | нет | `unsupported_commands` |
| Неизвестный идентификатор | тихо игнорируется | нет | `unknown_commands` |
| Обрезанный payload | отбрасывается до разбора аргументов | нет | `truncated_payloads` |

Молчание — намеренный выбор: прошивка VESC ведёт себя так же, а VESC Tool
рассчитан на отсутствие ответа (у него на каждый запрос свой таймаут).
Отправка «ошибки» в ответ на неизвестную команду не предусмотрена протоколом и
сбивала бы разбор на стороне Tool.

Соединение не разрывается ни в одном из случаев. Проверено в
`tests/protocol/test_protocol.c` и на живом сокете в интеграционном прогоне.

## Заблокированные команды управления мотором

ТЗ v0.4 §10: управление моторами запрещено, вывод физически невозможен.

| Команда | ID |
|---|---|
| `COMM_SET_DUTY` | 5 |
| `COMM_SET_CURRENT` | 6 |
| `COMM_SET_CURRENT_BRAKE` | 7 |
| `COMM_SET_RPM` | 8 |
| `COMM_SET_POS` | 9 |
| `COMM_SET_HANDBRAKE` | 10 |
| `COMM_SET_DETECT` | 11 |
| `COMM_SET_CURRENT_REL` | 84 |

Блокировка стоит **в диспетчере**, до всякой интерпретации аргументов. Даже
если бы за ней стоял настоящий CAN, эти команды до него не дошли бы. Сейчас за
ней стоит mock: `logical_motor_mock.c` не отправляет кадров вообще.

В трассировке это выглядит так:

```
RX  id=6   SET_CURRENT              len=5
!!  id=6   SET_CURRENT              len=5  motor command BLOCKED (mock backend, no CAN output)
```

## Известные, но не реализованные

| Команда | ID | Почему не нужна | Последствие |
|---|---|---|---|
| `COMM_GET_MCCONF` / `_DEFAULT` / `COMM_SET_MCCONF` | 13–15 | FloatCore не контроллер мотора; при hw_type = CUSTOM_MODULE VESC Tool их не запрашивает | Шкалы в Refloat UI берутся из локальных значений VESC Tool (см. `refloat_qml_dependencies.md` §3) |
| `COMM_GET_APPCONF` / `_DEFAULT` / `COMM_SET_APPCONF` | 16–18 | То же | Страница App Settings пуста |
| `COMM_JUMP_TO_BOOTLOADER`, `COMM_ERASE_NEW_APP`, `COMM_WRITE_NEW_APP_DATA` | 1–3 | Обновление прошивки через VESC Tool не входит в задачу | Страница Firmware неработоспособна |
| `COMM_TERMINAL_CMD` | 20 | Терминала у FloatCore нет | Команды терминала без ответа |
| `COMM_DETECT_*` | 24–28, 57, 58 | Детект параметров мотора — операция контроллера | — |
| `COMM_REBOOT` | 29 | Перезагрузка по запросу пока не нужна | — |
| `COMM_FORWARD_CAN`, `COMM_CAN_FWD_FRAME` | 34, 85 | Проксирование CAN запрещено на этом этапе | Нельзя достучаться до FSESC через FloatCore |
| `COMM_GET_IMU_DATA` | 65 | Страница IMU в VESC Tool; данные IMU и так видны в Refloat UI | Пустая страница IMU |
| `COMM_GET_VALUES_SETUP` / `_SELECTIVE` | 47, 51 | Setup-значения относятся к группе ESC на CAN | Страница Setup RT пуста |
| `COMM_GET_STATS`, `COMM_RESET_STATS` | 128, 129 | Статистика поездок ведётся Refloat | Пустая страница Statistics |
| `COMM_LISP_*` | 130–139, 152 | LispBM в FloatCore отсутствует: Refloat — нативный код | Страница VESC Packages / Scripting не работает |
| `COMM_FILE_*` | 140–144 | Файловой системы нет | — |
| `COMM_LOG_*` | 145–148, 151 | Логирование на SD относится к VESC Express | — |
| `COMM_BMS_*` | 96–101, 113, 114, 136, 137 | BMS-интеграция Refloat выключена по умолчанию | Страница BMS пуста |
| `COMM_IO_BOARD_*` | 122–124 | Другой класс устройств | — |
| `COMM_PSW_*` | 111, 112 | Другой класс устройств | — |
| `COMM_GET_GNSS` | 150 | GNSS нет | — |
| `COMM_QMLUI_ERASE`, `COMM_QMLUI_WRITE` | 120, 121 | QML вшит в прошивку и не перезаписывается снаружи | Попытка залить свой QML молча игнорируется |
| `COMM_GET_QML_UI_HW` | 117 | Своего HW-интерфейса у нас нет, `qml_hw = 0` | VESC Tool и не запросит |
| `COMM_SET_ODOMETER`, `COMM_SET_BATTERY_CUT`, `COMM_SET_BLE_*`, `COMM_SET_CAN_MODE` | 86–89, 110 | Настройки контроллера | — |

## Когда добавлять новую команду

Правило из ТЗ: **сначала подтвердить необходимость**. Порядок:

1. Включить трассировку (`--trace`) и воспроизвести сценарий, которого не хватает.
2. Найти в логе команду, оставшуюся без ответа, и посмотреть на счётчик
   `unsupported_commands`.
3. Убедиться по исходникам VESC Tool, что отсутствие ответа действительно
   ломает нужный сценарий, а не просто оставляет пустую страницу.
4. Только после этого реализовывать — и добавлять негативный тест.

Счётчики сессии печатаются при разрыве соединения:

```
[host] сессия завершена: RX 203 кадров, TX 202, CRC-ошибок 0,
       неподдержанных команд 0, заблокированных моторных 0
```
