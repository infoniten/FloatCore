# Расчёт загрузки шины CAN

Пересчёт по ТЗ v0.2 §3 — с учётом реального формата кадра, битстаффинга, ACK и
межкадрового интервала. Заменяет прикидку из `esp32_architecture.md` §6.

## 1. Длина расширенного кадра (CAN 2.0B, 8 байт данных)

| Поле | Бит |
|---|---|
| SOF | 1 |
| Арбитраж: 11-бит база + SRR + IDE + 18-бит расширение + RTR | 32 |
| Управление: r1, r0, DLC | 6 |
| Данные | 64 |
| CRC + разделитель | 16 |
| ACK slot + разделитель | 2 |
| EOF | 7 |
| Межкадровый интервал (IFS) | 3 |
| **Итого без стаффинга** | **131** |

Битстаффинг применяется к участку SOF…CRC — это 118 бит. Худший случай добавляет
`floor((118 − 1) / 4) = 29` бит.

* **Худший случай: 160 бит/кадр**
* **Практическое среднее (стаффинг ~5 %): 135 бит/кадр**

Протокол VESC использует только расширенные идентификаторы, поэтому короткие кадры в
расчёте не участвуют.

## 3. Загрузка шины

### Контур 500 Гц (целевой для MVP)

| Битрейт | Средняя загрузка | Худший случай | Запас до 30 % | Запас до 50 % |
|---|---|---|---|---|
| **500 кбит/с** | 216.5 кбит/с = **43.3 %** | 256.6 кбит/с = **51.3 %** | **отрицательный** | −1.3 % |
| **1 Мбит/с** | 216.5 кбит/с = **21.7 %** | 256.6 кбит/с = **25.7 %** | +4.3 % | +24.3 % |

### Контур 832 Гц (если позже поднимать частоту)

| Битрейт | Средняя загрузка | Худший случай |
|---|---|---|
| 500 кбит/с | 306.2 кбит/с = **61.2 %** | 362.9 кбит/с = **72.6 %** |
| 1 Мбит/с | 306.2 кбит/с = **30.6 %** | 362.9 кбит/с = **36.3 %** |

## 4. Задержка, а не только пропускная способность

Для контура важнее не утилизация, а время от `mc_set_current()` до появления тока.

Идентификаторы протокола VESC: `id = (packet_type << 8) | controller_id`. У команд
`SET_DUTY = 0`, `SET_CURRENT = 1`, у телеметрии `STATUS = 9`, `STATUS_2 = 14`,
`STATUS_3 = 15`, `STATUS_4 = 16`, `STATUS_5 = 27`, `STATUS_6 = 28`.

Численно меньший идентификатор = **более высокий** приоритет, поэтому **команды тока
всегда выигрывают арбитраж у телеметрии**. Это снимает главный риск: очередь статусов
не может задержать команду.

Худшая задержка второго кадра команды (для VESC B):

| Битрейт | Время кадра (160 бит) | Блокировка идущим кадром | Свой первый кадр | **Итого до постановки тока на B** |
|---|---|---|---|---|
| 500 кбит/с | 320 мкс | 320 мкс | 320 мкс | **~640–960 мкс** |
| 1 Мбит/с | 160 мкс | 160 мкс | 160 мкс | **~320–480 мкс** |

При периоде контура 2000 мкс (500 Гц) на 500 кбит/с задержка съедает до 48 % периода —
это заметный фазовый сдвиг в контуре и рассинхрон между моторами до 320 мкс.
На 1 Мбит/с — 24 % и 160 мкс соответственно.

## 5. Рекомендация

> **CAN 1 Мбит/с. Частота контура в MVP — 500 Гц.**

Обоснование:

1. На 500 кбит/с даже при 500 Гц худший случай — 51 % загрузки, то есть **нулевой запас**
   до общепринятого потолка 50 % для систем с жёстким реальным временем. Любая
   ретрансляция после ошибки выводит за него.
2. На 500 кбит/с нет запаса на рост: подъём контура до 832 Гц даёт 73 % — неприемлемо.
3. Задержка на 1 Мбит/с вдвое меньше, и рассинхрон между моторами падает до 160 мкс.
4. FSESC 4.20 и ESP32 TWAI поддерживают 1 Мбит/с штатно. Ограничение — длина шины
   (до ~25 м на 1 Мбит/с), для доски нерелевантно.

Дополнительно:

* **снизить частоту STATUS-сообщений** на обоих ESC до необходимого минимума. Refloat
  реально нужны STATUS_1 (ERPM, ток, duty), STATUS_4 (температуры, ток батареи) и
  STATUS_5 (напряжение, тахометр). STATUS_2/3/6 можно отключить: минус 200 кадров/с,
  −12.5 % загрузки при 500 кбит/с;
* терминаторы 120 Ом на обоих концах; без них ошибки и ретрансляции ломают весь расчёт;
* мониторить счётчики ошибок TWAI и переход в bus-off, bus-off → немедленный fault.

## 6. Что измерить на стенде

Расчёт — это верхняя оценка; измерению подлежат:

| Величина | Как | Критерий |
|---|---|---|
| Реальная загрузка шины | анализатор CAN, 60 с записи | ≤ 30 % средняя |
| Задержка «команда → ток» | GPIO-метка на входе в `mc_set_current` + токовые клещи | ≤ 500 мкс |
| Рассинхрон A/B | две токовые клещи одновременно | ≤ 200 мкс |
| Частота ошибок | счётчики TWAI за час езды | 0 bus-off, TEC/REC ≈ 0 |
| Реальная длина кадров | анализатор | сверка с моделью 135/160 бит |
