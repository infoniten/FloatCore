# Отклик мотора на малый ток: где начинается управление

Этап v0.9B §7-§14. Документ закрывает блокер 9b.

Колесо вывешено, доска закреплена, человек на доске не стоял. Пределы ESC
5 / −3 / 5 / −1 А не менялись, программный предел источника 1.0 А.

Измерения: `tools/motor_sweep.py` — инструмент, отдельный от боевой логики,
говорящий с консолью теми же командами, что доступны человеку.

---

## 1. Зачем измерять, если три точки уже были

На v0.9A получилось: 0.2 А — ничего, 0.5 А — начало отклика, 1.0 А — уверенное
вращение. Из этого напрашивался вывод «мёртвая зона 0.5 А», и он был бы
преждевременным: за этими числами стоят **четыре разные величины**, и
различить их можно только измерением.

```
A  порог приёма команды        ESC вообще принял значение
B  первый измеримый ток        в обмотке что-то потекло
C  первое воспроизводимое      вал сдвинулся хотя бы раз
   движение
D  порог устойчивого вращения  вал крутится, а не дёргается
```

И главное: причина у мёртвой зоны может быть механической (трогание с места)
или электрической (регулятор). Для замкнутого контура это противоположные
диагнозы, и лечатся они по-разному.

## 2. Развёртка с места

Перед каждой точкой инструмент ждал полной остановки вала (`|ERPM| < 30`
непрерывно 1.2 с). Доказательство, что ожидание работало: на уровне 0.00 А
Δtach вышел ровно **0** — катящийся вал набрал бы шаги и при нулевой команде.

Батарея 40.2 В (мультиметр), 40.5 В по CAN, за все развёртки не изменилась.

| 0.00 | 0.00 | 0.000 | 0 | 0 / 0 | 0 / 0 |
| 0.10 | −0.01 | — | 0 | 0 / 0 | 0 / 0 |
| 0.15 | −0.02 | — | 0 | 1 / 0 | 0 / 0 |
| 0.20 | −0.02 | — | 0 | 0 / 0 | 0 / 0 |
| 0.25 | −0.01 | — | 0 | 1 / 0 | 2 / 1 |
| **0.30** | 0.02…0.04 | 0.08 | 136 | **25 / 16** | 24 / 15 |

Две колонки в ячейке — два повтора.

### Четыре порога, а не один

```
A  приём команды        всегда: ни одна команда не была отвергнута ESC
B  первый измеримый ток  0.30 А (0.02-0.04 А), отчётливо с 0.40 А (0.17 А)
C  первое движение       0.30 А — воспроизвелось оба раза
D  устойчивое вращение   0.40 А — ERPM прыгает со 136 до 667, впятеро
```

### Ток следует за командой только выше порога

```
команда  0.30  0.40  0.50  0.60  0.75  1.00
ток      0.03  0.17  0.30  0.42  0.62  0.90
```

Выше 0.4 А зависимость почти линейна с постоянным отставанием около 0.10 А.
Ниже — ток не просто мал, его нет: ESC **не выдаёт** запрошенную величину.

## 3. Решающий опыт: то же самое на вращающемся колесе

Если малый ток начинает действовать на уже вращающемся колесе, значит мёртвая
зона — это трогание с места, то есть механика. Проверяется прямо.

Схема: остановка → раскрутка 1.0 А на 800 мс → испытуемый ток 1.5 с. База для
сравнения — тот же опыт с командой 0.00 А, то есть чистый выбег.

| Команда, А | Δtach A | вывод |
|---|---|---|
| 0.00 (выбег) | 86 / 79 | база |
| 0.10 | 80 / 84 | неотличимо от выбега |
| 0.15 | 84 / 83 | неотличимо |
| 0.20 | 83 / 89 | неотличимо |
| 0.25 | 83 / 85 | неотличимо |
| 0.30 | 91 / 82 | неотличимо |
| **0.40** | **150 / 142** | отчётливый прирост |
| 0.50 | 257 / 235 | сильный прирост |

**Порог не сдвинулся.** На вращающемся колесе 0.30 А не добавляет ничего, а
0.40 А добавляет столько же, сколько с места.

Оговорка по методике: колонка `Δtach B` в этом опыте несравнима с `A` —
половины опрашиваются последовательно с интервалом около 0.5 с, и на
движущемся валу это даёт смещение. В развёртке с места вал стоял, поэтому там
обе колонки совпадали шаг в шаг.

## 4. Классификация причины

| Гипотеза | Вердикт |
|---|---|
| Трение покоя, трогание с места | **ИСКЛЮЧЕНА**: порог тот же на вращающемся колесе |
| Зубцовый момент | **ИСКЛЮЧЕНА** по той же причине |
| `l_min_duty` | **НЕ ПОДХОДИТ как единственная**: см. ниже |
| Электрическая, со стороны регулятора | **СОГЛАСУЕТСЯ** со всеми данными |

### Почему `l_min_duty` не объясняет

Счёт, предложенный на v0.9A, на стоящем моторе даёт порог около 0.63 А:

```
требуемая скважность = I · R / V = I · 0.32 / 40.2
при l_min_duty = 0.005  →  I = 0.63 А
```

Наблюдается 0.30-0.40 А, то есть вдвое ниже. И, что важнее, **на вращающемся
колесе этот механизм не работает вовсе**: там скважность задаётся
противо-ЭДС и составляет 0.06-0.12, то есть на порядок выше минимума. А порог
при этом остался прежним.

Значит `l_min_duty` в лучшем случае одна из причин на стоящем моторе, но не
та, что определяет границу.

**Точная причина по коду прошивки VESC не установлена.** Исходники bldc в
репозитории не вендорятся (кроме `confgenerator.c` для раскладки полей), и
делать утверждение о механизме без их чтения означало бы заменить одну
правдоподобную версию другой. Записано как открытый вопрос.

## 5. Торможение

Схема та же, испытуемый ток отрицательный. Батарея 40.2 В, до начала срезания
рекуперации 41.5 В — запас 1.3 В.

| Команда, А | Δtach A | I мотора | вывод |
|---|---|---|---|
| 0.00 (выбег) | 116 / 113 | 0.00 | база |
| −0.10 | 116 / 116 | 0.01 | нет эффекта |
| −0.20 | 105 / 112 | 0.02 | на грани |
| **−0.30** | **89 / 76** | 0.05 | торможение видно |
| −0.40 | 20 / 58 | 0.16 | сильное |
| −0.50 | −61 / −54 | 0.29 | вал развернуло назад |

**Отклик несимметричен:** торможение начинается около −0.30 А, разгон — около
+0.40 А. Предполагать симметрию было бы неверно.

Ток в батарею не превысил 0.03 А, напряжение не изменилось (40.5 В) —
рекуперации при таких скоростях и `l_in_current_min = −1 А` практически нет.

## 6. Сравнение половин

Раздельно пороги половин этим методом **получить нельзя**, и это следствие
архитектуры, а не упущение: моторы жёстко связаны одной осью, а координатор
по построению всегда посылает пару. Разделить их означало бы нарушить
инвариант, ради которого он написан.

Что сравнимо:

```
Δtach при команде 1.0 А        493 / 493  и  488 / 487   расхождение 0.2 %
ток при одной команде          0.05 и 0.06 А             в пределах шума
ERPM                           7118 и 7136               0.25 %
скважность                     0.722 и 0.651             11 %
```

Расхождение по скважности **не установлено**: половины опрашиваются
последовательно с интервалом 0.35 с, а вал в этот момент разгонялся. Для
вывода нужен одновременный отсчёт, которого текущая диагностика не даёт.

Записано как открытый вопрос, помоторная компенсация **не вводится**.

## 7. Момент

Подтверждённые постоянные: `Kt118 = 0.441`, `Kt100 = 0.449` Н·м/А.

```
идеальный электромагнитный момент   M = I · (Kt_A + Kt_B) = I · 0.890 Н·м/А
```

Но приравнивать его к моменту на колесе **ниже порога нельзя**: при команде
0.30 А формула обещает 0.267 Н·м, а измеренный ток составляет 0.03 А, то есть
фактический момент примерно 0.027 Н·м — в десять раз меньше. Идеальная
формула применима начиная примерно с 0.4-0.5 А, и то с поправкой на
отставание тока около 0.10 А.

## 8. Следствие для будущего контура балансировки

Факты, с которыми придётся считаться:

* команды ниже ≈0.3 А не производят **ничего** — ни тока, ни момента;
* устойчивое воздействие начинается с ≈0.4 А, и это **не** трение покоя:
  на вращающемся колесе порог тот же;
* отклик несимметричен: торможение включается раньше разгона;
* выше порога ток отстаёт от команды примерно на 0.10 А.

Для балансировки это означает мёртвую зону вокруг нуля шириной около
±0.35 А, то есть примерно ±0.31 Н·м суммарного момента. Интегральная часть
регулятора в такой зоне будет накапливаться, не производя действия, и
сработает скачком при выходе из неё.

**Никакая компенсация на этом этапе не вводится** — ТЗ прямо это запрещает, и
правильно: сперва надо знать причину мёртвой зоны по коду прошивки, иначе
компенсация будет лечить симптом. Направления, которые стоит рассмотреть
позже: прямая подача минимального тока, обратная характеристика мёртвой зоны,
запрет накопления интеграла внутри неё, либо изменение параметра VESC — но
только после того, как причина установлена.
